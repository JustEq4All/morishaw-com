## Architecture (do not change these)

- Framework: **Astro v5**, static output
- Build: `npm run build` → outputs to `dist/`
- Deploy command:
  ```bash
  NETLIFY_AUTH_TOKEN="$(cat ~/.openclaw/workspace/.netlify-token)" netlify deploy --dir=dist --site="e57afca7-f021-449f-9ed6-a7441aea2a0a" --prod
  # Note: if "Project not found", run first: netlify link --site e57afca7-f021-449f-9ed6-a7441aea2a0a
  ```
- Netlify token is stored at `~/.openclaw/workspace/.netlify-token` (600 perms) — models should read it from there, never ask Gilberto to re-paste.
- CMS: **TinaCMS** (migrated from Decap on 2026-08-21)
  - Schema: `tina/config.ts` (events, writings, talks, testimonials, site)
  - **Must-commit file:** `tina/tina-lock.json` (TinaCloud will NOT index branches without it)
  - Generated admin: `public/admin/index.html` (output of `tinacms build`) — do NOT edit by hand
  - Content token lives in env vars; the read-only content token is used at BUILD time only
  - **Publishing edits**: happens through the `/admin` login (Tina/GitHub-authorized account), NOT an API token
  - Content API: `https://content.tinajs.io/2.4/content/e76c03ef-4caf-445c-a0a4-b4aab6854e5a/github/master`
- Design system: `src/styles/global.css` — bronze/off-white/ink palette

## Adding Media (photos, videos)

### Preferred: TinaCMS media uploader (easiest — no server access)
- Once TinaCMS is enabled at `morishaw.com/admin`, photos are added via drag-and-drop right in the editor.
- Media is configured via `tina/config.ts` → `media.tina.mediaRoot: images/uploads`, `publicFolder: public`.
- Uploaded files land in `public/images/uploads/` and are committed to the repo by the CMS.
- You (or any model) never need to touch the VPS/server.

### Alternate: send photos in chat
- Drop the photo in chat → download → place in `public/images/` → optimize → build + deploy.

### Manual rules
- Place images in `public/images/` (or subfolder like `images/uploads/`)
- Reference in `.astro` as `/images/filename.jpg`
- Logos → `public/images/logos/` as PNG, max ~100KB
- Photos: JPG preferred, keep hero under ~200KB; WebP for max compression
- The two photo placeholders to wire real images into:
  - Hero: `src/pages/index.astro` (block: `hero__photo-placeholder`)
  - About: `src/pages/about.astro` (block: `about-photo-placeholder`)

## TinaCMS Build / Deploy Flow (replaces Decap)

```bash
cd ~/.openclaw/workspace/website/astro-site

# 1) Generate/refresh the Tina client + admin + lockfile (needs real client id + token):
TINA_CLIENT_ID="e76c03ef-4caf-445c-a0a4-b4aab6854e5a" \
TINA_TOKEN="<content-token>" \
  npx tinacms build

# 2) Standard Astro build:
npm run build

# 3) Commit (ALWAYS include tina-lock.json) + push:
git add -A && git commit -m "..." && git push origin master

# 4) Deploy:
NETLIFY_AUTH_TOKEN="$(cat ~/.openclaw/workspace/.netlify-token)" \
  netlify deploy --dir=dist --site="e57afca7-f021-449f-9ed6-a7441aea2a0a" --prod
```

### TinaCMS gotchas (learned 2026-08-21)
- **`tinacms build` fails with "Branch not on TinaCloud"** → run `tinacms dev` once (generates `tina-lock.json`), commit+push it, then **reindex the project in the Tina dashboard** (overview page).
- **"Index version 0 no longer supported"** → the Tina project needs a **Reindex** in `app.tina.io` (owner-level action; content token cannot do it).
- **Site URL must be registered** in Tina Cloud → Project → Site URLs (e.g. `https://gilberto-morishaw.netlify.app`). Missing it causes: *"Your TinaCloud config is missing for domain … Please add it to your projects site URLs."*
- Content token is **read-only by design**; never use it as the publish auth. Publishing = `/admin` login.
- When pasting the token into shell, use the **full** token — a truncated/ellipsis value causes `Cannot convert argument to a ByteString`.
